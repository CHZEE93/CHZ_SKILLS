# Web_Design_Pallet

화면을 그리기 전에 **누가, 어느 대상을 선택해, 어떤 상태로 바꾸는가**를 한 문장으로 적는다. 예: “접수 담당자가 대기 목록에서 예약자를 찾아 접수를 확정한다.” 의료 용어를 그대로 옮기지 말고, 프로젝트의 실제 대상과 업무 상태로 치환한다. 제품 기능과 데이터 구조는 사용자의 요구사항을 따른다.

## 작업면 선택

| 사용자의 다음 결정 | 보여줄 화면 | 맥락을 유지하는 방법 |
|---|---|---|
| 누구를 처리할까? | 좁은 탐색 영역 옆에 검색·상태별 목록 | 선택 행과 상세 제목에 같은 대상 식별자를 표시한다. 동명이면 보조 식별자를 더한다. |
| 이 대상에게 무엇을 기록할까? | 넓은 중앙 편집면, 필요할 때만 우측 이력·첨부·도구 | 과거 기록과 수정 중인 기록을 시각적으로 분리한다. 검색 결과를 삽입해도 초점은 원래 편집면으로 돌아온다. |
| 어떤 문서를 만들거나 발급할까? | 서식 목록 → 작성·검토 → 발급 결과 | 대상과 서식명을 확정 버튼 가까이에 남긴다. 초안 저장과 최종 발급은 다른 행동으로 표시한다. |
| 여러 건 중 무엇이 예외인가? | 기간·상태 필터, 행 중심 표, 선택한 건의 세부 정보 | 오류나 미완료 행을 바로 좁힐 수 있게 한다. 목록 복귀 시 기간·필터·스크롤을 보존한다. |
| 언제 배치할까? | 날짜·시간이 기준인 일정표와 예약 상세 | 빈 슬롯 생성과 기존 예약 편집을 구별한다. 좁은 화면은 같은 날짜의 시간순 목록으로 전환한다. |

먼저 한 회차의 업무가 끝나는 최소 흐름을 구현한다. 조회 전용 화면까지 세 칸으로 채우지 않는다. 목록·편집·이력의 연결은 [장비 수리 작업대 예제](index.html)에서 확인한다. 실행 방법은 [README](README.md)에 있다.

## 시각 언어

- 영상에서 반복되는 밝은 작업면, 옅은 청회색 바탕, 가는 경계, 작은 파란 실행 버튼을 역할 단위로 적용한다. 정확한 원제품 색상·치수는 측정하지 않았다. 기존 제품 토큰이 있으면 그 역할에 매핑한다.
- 목록은 이름·상태·시간처럼 비교할 필드를 같은 열에 정렬한다. 섹션마다 큰 카드나 아이콘을 추가하면 보이는 행 수가 줄어든다. 긴 설명은 상세에 두고 목록에는 판단에 필요한 보조 문구 한 줄만 둔다.
- 지배적인 버튼은 현재 단계의 **동사 + 대상**으로 작성한다. 선택 행은 글자색뿐 아니라 배경·선택 표식으로, 오류는 색뿐 아니라 메시지로 구분한다. 영상 자막의 파란 띠, 타이틀 카드와 홍보 삽화는 제품 UI 토큰이 아니다.
- 시작값이 필요한 새 구현에서는 본문 14–16px, 행 높이 36–44px, 얇은 구분선부터 시험한다. 이는 **구현 제안**이다. 확대·긴 한글 라벨·터치 환경에서는 줄바꿈과 행 높이 증가를 허용한다.

## 상태와 중단 처리

검색·선택·입력·확정·결과를 분리한다. 검색 결과 없음에는 조건 변경을, 첫 사용 상태에는 첫 항목 생성을 제시한다. 요청 실패 시 입력을 유지하고 재시도 위치를 알려준다. 화면 오른쪽 아래에 확인 버튼이 있다면 어떤 패널에 적용되는지 경계 안에서 명확히 한다. 단순 조회는 인라인이나 보조 패널, 짧고 완결되는 입력은 대화상자, 긴 편집은 주 작업면이 적합하다.

작은 화면에서는 목록 → 상세 → 편집을 순서대로 보여준다. 복귀 시 선택 대상을 유지한다. 키보드로 행을 선택하고, 대화상자를 닫으면 호출한 항목으로 돌아와야 한다. 데모에는 가상 데이터만 사용하며 영상에서 보이는 환자 정보·기록·이미지를 복제하지 않는다.

## 완료 판단

대표 업무 하나를 처음부터 끝까지 수행해 본다. 예컨대 ‘작업 큐 → 대상 선택 → 템플릿 삽입 → 첨부 확인 → 저장 → 큐 복귀’에서 매 단계 대상이 식별되고, 저장 실패 후에도 작성 내용이 남으며, 성공 후 같은 행의 상태가 갱신되는지 확인한다. 완료 상태, 빈 목록, 오류, 좁은 화면을 보여줄 수 있어야 한다. 임상·청구 규칙은 이 스킬에서 추론하지 않는다.
