# Web_Design_Pallet

[공식 매뉴얼](https://dr.pltt.cloud/manual)의 영상 11편(약 26분)을 3초 간격 1080p 프레임 530장으로 읽어 정리한 규칙이다. 화면 구조는 [references/patterns.md](references/patterns.md), 색·크기 값은 [references/tokens.md](references/tokens.md), 장면별 근거는 [references/video-evidence.md](references/video-evidence.md)에 있다. 바로 쓸 수 있는 CSS는 [assets/pallet.css](assets/pallet.css), 동작 예제는 [index.html](index.html)이다.

## 1. 먼저 정할 것

1. **작업 대상 한 건**이 무엇인가(환자 접수 1건, 발주서 1건, 작업지시 1건). 이 단위가 목록의 행, 헤더 요약 바, 하단 액션 바의 주어가 된다.
2. **그 대상이 이동하는 장소와 상태**(진료실01·방사선실·수납실 / 대기·진행중·우선대기). Pallet 화면의 주 버튼은 저장이 아니라 "다음 장소로 보내기"다.
3. **역할별로 바뀌는 부분**(진료실은 기록·처방, 원무과는 수납·문서). 같은 골격에서 가운데 열만 바꾼다.

## 2. 레이아웃 골격

```
[내비 160][대상 목록 232][ 헤더 요약 바 ──────────────────────────────── ✕ 닫기 ]
          [            ][이력 300][ 작업 카드 스택 (가변) ][참고 260][협업 230][레일 48]
          [            ][        ][ 하단 액션 바: 현재 위치 | 목적지⌄ 상태⌄ ▶보내기 ]
```

- 내비와 대상 목록은 **어떤 작업을 열어도 사라지지 않는다.** 대상을 고르지 않았을 때 작업면은 빈 화면이 아니라 "다음 행동" 카드(다음 환자 부르기, 신규 등록, 접수 신청 n건)로 채운다.
- 작업면은 거터 위 **하나의 흰 카드**이고 열은 1px 세로선으로만 나눈다. 열마다 그림자나 별도 카드를 두지 않는다.
- 가운데 작업 열은 업무 단계 카드(진료기록 → 진단 및 처방 → 수납 → 문서발급)를 세로로 쌓는다. `⣿ 화면 구성` 팝오버의 체크리스트로 역할별로 켜고 끈다. 단계마다 페이지를 옮기지 않는다.
- 오른쪽 아이콘 레일(메신저·공지·북마크·검사결과)은 **같은 열 슬롯의 내용을 교체**한다. 패널을 더 늘리지 않는다.
- 관리·라이브러리·통계 화면은 내용 폭만큼만 카드를 둔다. 요약 카드는 약 600px, 편집기는 약 720px로 두고 오른쪽 캔버스는 비워 둔다. **데이터 테이블만 전체 폭**을 쓴다.

## 3. 화면 유형별 처방

| 업무 | 구조 | 핵심 규칙 |
|---|---|---|
| 접수·대기 | 장소별 그룹 카드 → 2줄 행 | 그룹 헤더: 담당자 아바타·이름·인원수·접기. 행 1줄은 이름+상태, 2줄은 성별·나이·목적. 빈 그룹도 "대기 환자가 없습니다."로 남긴다. |
| 한 건 처리(차트) | 헤더 요약 바 + 다열 작업면 | 요약 바의 칩(보험·담당의·바이탈·가족)은 각각 hover 미리보기, click 편집 모달의 진입점이다. |
| 반복 행 입력(처방) | 섹션 고정 순서 리스트 | 상병 → 진찰료 → 약 → 검사 → 문서 순서. 수량·횟수·일수는 밑줄형 인라인 입력 3칸(가운데 정렬, 고정 폭). |
| 일정 | 미니 달력·예약 표(27%) + 시간×리소스 그리드 | 빈 슬롯도 블록으로 그리고 블록에 시간 범위와 `예약/정원`을 쓴다. 리소스마다 색 1개를 정해 옅은 채움과 진한 글자·테두리로 쓴다. |
| 검토·제출(청구) | 배치 목록 1/3 + 상세 2/3 | 오류는 `집계 배지 → 행 ⚠ n건 → 상세 배너 → 원인 화면 딥링크` 4단으로 보여 준다. 발급 후에는 잠그고 액션 라벨을 바꾼다(`발급하기`→`내려받기`). |
| 통계 | 필터 줄 + 라벨-값 요약 카드 / 요약 카드→테이블 | 조회 버튼 없이 즉시 반영한다. 화면에는 집계만 두고 원장은 `↗ 내보내기`로 넘긴다. |
| 인사이트 | 푸시형 월간 리포트 → 3열 차트 카드 | KPI는 `라벨 → 큰 값 → ▲빨강/▼파랑 % + 비교 기준` 순서. 서술문 속 수치는 형광펜으로 강조한다. |
| 라이브러리 | 폴더 트리 300 + 편집기 720 | 폴더 끝에 인라인 `+ 생성`. 편집기 헤더에 실시간 합계를 둔다. 같은 트리가 사용 지점(차트) 옆 패널로 다시 나온다. |
| 자동 발송 설정(CRM) | 규칙 행 카드 | 행은 `제목 + ⓘ 미리보기 / 회색 설명 1줄 / 오른쪽 토글`. 바꾸면 `변경사항 저장`이 나타나고, 비용이 생기면 경고 확인을 거친다. |

## 4. 상호작용 문법

- **이동은 저장과 한 번에.** 주 버튼 옆에 `[목적지⌄][상태⌄][▶ 보내기]`를 붙인다. 접수 모달도 `[대기열⌄][대기⌄][접수]`다. 퇴원·귀가 같은 이탈 목적지는 같은 메뉴 맨 아래에 빨간 글자로 둔다.
- **목록 행 클릭은 이동 메뉴**(`'방사선실'로 보내기`, 현재 그룹은 제외)를 띄운다. 실행하면 행이 새 그룹으로 옮겨져 잠시 강조되고, 하단 가운데 다크 토스트가 문장으로 결과를 알린다. 되돌릴 수 있는 이동에는 `되돌리기`를 넣는다.
- **연속 업무는 모달을 교체해 잇는다**(`등록 후 접수` → 같은 자리에서 접수 모달). 기존 대상의 폼에는 왼쪽에 읽기 전용 맥락 패널(최근방문기록·주요기록·알러지)을 붙인다.
- **검색은 하나의 입력에 유형 탭**(`전체(요약)|상병|오더|오더세트|처방아이템|단축어`)을 두고, 그룹마다 `더보기`를 달고, 일치 문자는 노란 형광으로 표시한다. 결과 행에는 동명이인을 가를 정보(번호 칩·연락처·마스킹 주민번호·최근방문)를 넣는다. 결과가 없으면 신규 등록 CTA를 고정해 둔다.
- **파생값은 즉시 다시 계산한다.** 처방을 추가하면 수납 금액·처방전 문서 행·총 단가가 바로 바뀐다. 서버 재계산이 필요한 집계에는 `↻`나 `새로고침` 링크를 둔다.
- **검증·외부 조회 결과는 필드 바로 아래**에 `✅ 2022-09-30 11:32 자격조회 완료`처럼 시각과 함께 쓴다. 종속 필드는 숨기지 않고 비활성으로 보여 준다.
- **충돌은 먼저 인라인 경고로** 알린다(`ⓘ 예약 슬롯이 가득 찬 시간입니다.`). 삭제는 상태 이동(예약취소 탭)으로 기록을 남긴다.

## 5. 모달 문법

- 제목은 서술문이다(`원청구서를 생성합니다.`, `사용자아이템을 생성합니다.`). 편집 모달의 제목은 항목 이름이고, 그 아래 읽기 전용 요약 박스를 둔다.
- 라벨은 입력 위에 두고, 필수는 라벨 뒤 `*`로 표시한다(빨간색 아님). 필수가 비어 있으면 primary를 연한 파랑으로 비활성화한다.
- 푸터 배치: 왼쪽 끝에 `삭제·점검 종료·예약취소`(빨강 아웃라인), 오른쪽 끝에 `취소`(아웃라인/텍스트) → 보조 저장(파랑 아웃라인) → 주 저장(파랑 채움).
- 작업의 기준값(`남은 금액 20,000원`)은 모달 맨 위 회색 박스에 다시 보여 준다. 선택값에 따라 필드 묶음이 바뀐다(카드: 할부 / 현금: 현금영수증·승인번호).
- 확인 다이얼로그는 폭 약 360px이고 ⚠ 아이콘, 질문, 필요하면 사유 입력, `취소` `확인` 순서로 둔다.

## 6. 시각 규칙 (값은 tokens.md)

- 캔버스는 회청색 `#E6EDF5`, 표면은 흰색, primary는 단일 블루 `#5A9DFC`(모달 확정·눌림은 `#347DEB`)다. 선택 행·활성 내비에는 `#EEF7FE` tint를 쓴다.
- 구분은 1px `#E5E8EE` 선으로 한다. **그림자는 떠 있는 레이어(팝오버·메뉴·모달·토스트·검색 드롭다운)에만** 쓴다.
- radius: 칩 4 / 입력·버튼 6 / 카드 8 / 모달 12. 세그먼트·토스트·선택 날짜는 pill이다.
- 상태는 색 하나와 글자를 함께 쓴다. 대기는 주황 글자(배경 없음), 진행중은 파랑 tint 칩, 우선대기·성공은 청록, 신규는 이름 뒤 빨간 점, 요청은 빨강 아웃라인 칩, 비급여는 빨강 글자, 원내는 보라 글자, 주상병은 초록 `주`다. 채움색은 primary 버튼과 완료 칩에만 쓴다.
- 밀도: 컨트롤 높이 32, 테이블 행 36–40, 2줄 목록 행 52, 섹션 제목 14 semibold, 본문 13, 메타 11–12 회색이다. 표에는 세로선과 줄무늬를 넣지 않는다. 금액은 오른쪽 정렬하고 천 단위 콤마와 단위(`원`·`명`·`건`)를 붙인다.
- 아이콘은 1.5px 라인이고 회색, 활성일 때 파랑이다. 오더 종류는 행 앞 아이콘(✚ 상병, ◇ 처치, 알약, 카메라, 문서)으로 구분한다.

## 7. 다른 도메인에 옮길 때

| Pallet 개념 | ERP | MES |
|---|---|---|
| 진료실 그룹 카드 / 대기 상태 | 결재함·담당자별 문서 묶음 / 작성중·승인대기 | 라인·공정별 작업지시 / 대기·진행·보류 |
| 헤더 요약 바 | 문서번호·거래처·통화·납기 | 작업지시·품목·LOT·설비 |
| 진단 및 처방 행 + 인라인 수량 | 품목 행 + 수량·단가·납기 | 실적 행 + 양품·불량·단위 |
| `[수납실⌄][대기⌄][▶보내기]` | `[다음 결재자⌄][승인요청]` | `[다음 공정⌄][완료]` |
| 오더세트 / 단축어 | 품목 묶음 템플릿 | 작업표준·BOM 묶음 |
| 심사점검모드 / 원청구서 오류 | 마감 전 검증 / 전표 오류 | 출하 전 검사 / 불합격 |

명칭과 승인 규칙은 대상 시스템의 정의를 따르고, 위 표는 구조 대응으로만 쓴다.

## 8. 완료 점검

- [ ] 대상을 연 상태에서 목록과 내비가 계속 보이는가. 닫으면 같은 행으로 돌아오는가.
- [ ] 보내기·상태 변경 뒤 목록 그룹, 카운트(`대기 6`→`대기 5`), 토스트가 같은 결과를 보이는가.
- [ ] 필수 미입력, 슬롯 초과, 검증 오류가 필드 옆과 집계 배지에 모두 나타나는가. 오류 상세에서 원인 화면으로 바로 가는가.
- [ ] 그림자가 떠 있는 레이어에만 있는가. 상태가 색과 글자를 함께 쓰는가.
- [ ] 빈·로딩·결과 없음 상태가 아이콘 + 한 줄 + 다음 행동 안내로 각각 정의되어 있는가.
- [ ] 1280px에서 보조 열(협업·참고)이 레일로 접히고 작업 열이 640px 이상 남는가.

영상 속 환자 정보·병원명·브랜드 로고·안내 자막은 옮기지 않는다. 예제에는 가상 데이터를 쓴다.
