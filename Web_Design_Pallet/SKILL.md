# Web_Design_Pallet

레퍼런스에 맞춘 시안 요청이면 [기본 차트](index.html)를 출발점으로 삼는다. 먼저 [README의 장면 비교표](README.md)에서 요청된 업무와 대응하는 시점을 확인한다. 의료 화면을 요청받았다면 도메인까지 유지한다. 다른 업종으로의 치환은 요청이 있을 때만 한다.

## 차트의 공간 계약

1. **공통 상단:** 기관 식별, 현재 업무, 환자 검색, 신규 접수. 검색 결과를 고른 후 차트번호가 목록과 상세에서 일치해야 한다.
2. **왼쪽의 서로 다른 두 목록:** 가장 왼쪽은 업무 전환이다. 그 옆은 진료실별 환자 큐다. 대기·진료중·수납대기는 환자 상태이고 ‘차트·예약·통계’는 업무 위치이므로 같은 탭으로 합치지 않는다.
3. **선택 환자 띠:** 큐 오른쪽부터 차트 끝까지 이어지는 낮은 한 줄에 식별자·이름·기본 정보·진료 맥락을 둔다. 별도 프로필 카드로 작업 높이를 차지하지 않는다.
4. **과거와 현재:** 내원이력은 날짜마다 읽고 펼치는 좁은 열이다. 가장 넓은 열은 오늘 진료기록과 그 내부의 첨부 영역, 바로 아래 진단·처방이다. 저장은 현재 기록에 작용하고 과거 기록 선택은 읽기 동작이다.
5. **두 보조 열:** 오더세트는 검색·선택하여 현재 차트에 삽입하는 도구다. 가장 오른쪽 환자기록은 팀 메모를 읽고 추가하는 자리다. 환자기록을 의학적 경과 기록과 섞거나 오더세트 클릭만으로 방문을 마감하지 않는다.
6. **인계:** 현재 작업면 하단에서 다음 대기열로 보낸다. 대상과 다음 상태를 버튼에서 읽을 수 있어야 한다. 목록과 집계가 같은 상태를 사용해야 한다.

## 시각 규칙

데스크톱 첫 화면의 주인공은 열린 차트다. 큰 제목·설명·영웅 영역·카드형 통계로 시작하지 않는다. 밝은 면 사이를 1px 경계로 나누고, 작업 바깥과 보조 메모 영역에만 옅은 청회색을 쓴다. 실험용 시작값은 메뉴 100–115px, 대기열 150–200px, 나머지에서 현재 기록에 가장 큰 폭을 배정한다. 이 수치는 원본 코드의 토큰이 아니다. 반응형에서 글자를 무작정 줄이기보다 이력·세트·메모를 차례로 재배치하고 선택 대상·초안을 유지한다.

큐는 줄 단위로 스캔한다. 그룹명·건수, 이름·상태, 보조 식별자가 같은 위치에서 반복되어야 한다. 선택 행과 주요 실행을 파란색으로 표시하되 텍스트와 선택 표식도 남긴다. 메모는 작성 주체·시점·내용으로 읽고, 여러 업무가 동시에 보일 때 실행 버튼은 자기 패널 안에 둔다. 영상의 시연 자막·마우스 강조·홍보 삽화는 제품 컨트롤이 아니다.

## 화면을 바꾸는 기준

- 진단·처방 검색과 짧은 발급 입력은 차트 맥락을 보존하는 창으로 연다. 취소 시 작성 내용을 변경하지 않고, 적용 시 선택 대상의 기록만 갱신한다.
- 예약은 시간 × 진료 구역 격자, 청구는 처리 대상 × 검토 상태 표가 중심이다. 진료 화면의 여섯 열을 이 화면들에 반복하지 않는다.
- 통계는 같은 조건의 수치를 비교하는 표, 인사이트는 분포·추세를 파악하는 그래프다. 표와 그래프가 동일한 데이터 범위를 써야 한다.
- 라이브러리의 서식 원본, 현재 선택한 미리보기, 차트에 삽입한 사본을 구분한다. 진료 중 편집이 공유 서식 원본을 바꾸면 안 된다.

## 검수

대기열의 A 환자를 선택해 기록 작성 → B로 전환 → A로 복귀 → 오더 삽입 → 메모 등록 → 다음 대기열로 인계까지 수행한다. 다른 대상에게 내용이 섞이지 않는지 확인한다. 검색 결과 없음, 비어 있는 발급 이력, 좁은 화면, 키보드로 대화상자 열기·닫기도 살핀다. 예제는 가상 데이터로 구성하며 실제 개인 기록·브랜드 자산을 복제하거나 영상만 보고 임상 및 청구 규칙을 단정하지 않는다.
