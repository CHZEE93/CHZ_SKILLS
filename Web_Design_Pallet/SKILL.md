# Web_Design_Pallet

먼저 “누가 어떤 단위의 일을 선택해 무엇을 확인하고 어떤 결과를 남기는가”를 정한다. 구매 담당자에게 거래처는 조회 기준일 수 있지만 편집 대상은 **발주서의 품목 행**이다. 현장 작업자에게도 작업지시 하나에 여러 공정이나 LOT가 있을 수 있다. 목록의 한 행, 편집 초안, 확정 동작이 각각 어느 단위에 속하는지 프로젝트의 모델에서 확인한다.

## 업무에 따라 첫 화면을 정한다

| 주된 결정 | 중심 화면 | 유지할 맥락 |
|---|---|---|
| 여러 건 중 예외를 고른다 | 필터와 비교 가능한 열을 가진 표 | 정렬·필터·선택 위치. 상세를 닫으면 같은 행으로 돌아간다. |
| 한 건을 작성하거나 검토한다 | 낮은 식별 띠 아래 가장 넓은 편집면. 비교가 필요한 이력만 옆에 둔다. | 문서번호 또는 작업지시·공정 식별자, 현재 상태, 초안 |
| 설비·인력·시간을 배치한다 | 시간 × 자원 일정표 | 날짜·교대·설비 범위. 슬롯을 열어도 보고 있던 시간이 유지된다. |
| 작업자가 한 공정을 수행한다 | 현재 지시·품목·LOT 확인 후 실적 입력과 다음 행동 | 현장에서 구별해야 할 단위와 피드백. 터치 단말에는 사무실용 다열 표를 축소하지 않는다. |
| 수치나 추세를 판단한다 | 정확한 대조는 표, 시간 변화나 분포는 그래프 | 기간·단위·집계 범위. 요약에서 원본 행으로 내려갈 때 조건을 전달한다. |

## 화면 구성 원칙

- **탐색과 상태를 분리한다.** 구매·입고·재고는 업무 메뉴이고, 작성 중·승인 대기는 문서 상태다. 같은 탭 행에 섞지 않는다. 선택 목록을 계속 볼 이유가 없으면 편집면까지 억지로 나란히 두지 않는다.
- **이력·입력·참고의 경계를 둔다.** 이전 확정 내역은 읽기 영역에, 지금 바꾸는 필드는 편집 영역에 둔다. 표준 서식·오더세트·작업표준은 필요한 시점에 열고 적용 대상을 명시한다. 팀 메모는 승인 이력이나 검사 판정을 대신하지 않는다.
- **저장과 업무 전이를 구별한다.** ‘초안 저장’, ‘승인 요청’, ‘실적 확정’처럼 결과가 드러나는 동사를 쓴다. 버튼 활성 조건과 다음 상태는 실제 권한·서버 응답에 맞춘다. 저장 실패 시 초안과 선택 행을 보존하고 성공 전에는 완료 건수에 넣지 않는다.
- **밀도는 비교를 위해 쓴다.** 밝은 작업면, 가는 경계, 정렬된 숫자·단위, 한 줄의 식별 정보가 기본이다. 상태는 색과 글자로 함께 표시한다. 기존 디자인 토큰이 있으면 선택·강조 역할을 매핑한다. 좁은 화면에서는 식별자와 현재 행동을 먼저 남기고 이력·참고 자료를 접는다.

## 도메인 적용 예시

**ERP · 구매발주 검토.** 목록에는 발주번호·거래처·납기·통화·상태를 두고, 상세에는 품목별 수량·단위·단가와 합계를 둔다. 같은 품목이 두 행에 있어도 행별 납기와 초안이 섞이지 않게 한다. 부분입고 화면이라면 주문량·기입고량·이번 입고량을 나란히 비교한다. 발주 승인과 입고 확정은 다른 업무이므로 한 버튼으로 처리하지 않는다. 승인 단계·금액 계산 규칙은 해당 ERP 정의를 따른다.

**MES · 생산 실적 등록.** 라인·교대로 범위를 좁히고 작업지시번호·공정·품목·LOT를 확인한 뒤 실적을 입력한다. 목표·이전 누계·이번 입력을 구분하고 양품·불량 수량에는 단위를 붙인다. 스캔 대상이 선택한 지시와 불일치하면 어느 값이 다른지 보여주고 기존 초안을 보존한다. 실적 등록, 검사 판정, 후공정 인계는 현장 흐름에서 구분되는 경우 각각 별도 행동으로 둔다. LOT 분할·재작업·완료 조건은 시스템 정의가 있을 때만 구현한다.

**EMR · 외래 차트.** 닥터팔레트 재현 요청에는 [차트 미리보기](index.html)와 [매뉴얼 장면 비교표](README.md)를 사용한다. 진료실별 환자 큐 → 내원이력 → 오늘 기록·첨부와 진단·처방 → 오더세트 → 직원 공유 메모의 구분을 유지한다. 이 여섯 영역은 외래 차트의 구체적 해법이며 다른 도메인의 기본 열 개수가 아니다.

## 검수 시나리오

A의 한 행에 작성 → B 확인 → A 복귀 → 확정 실패 → 재시도 → 다음 담당자 목록 반영을 따라간다. 대상·행·LOT가 바뀌거나 다른 건에 수량이 더해지지 않는지 본다. 확정 후 상세·목록·집계가 같은 결과를 보여야 한다. 대량 처리 화면은 전체 선택의 범위와 일부 실패한 행을, 현장 입력 화면은 스캔 오류 후 초점과 중복 제출을 추가로 확인한다.
